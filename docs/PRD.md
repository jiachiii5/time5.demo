# 產品需求文件 (PRD) - 感官封存模組

## 1. 專案概述
- **背景與動機**：人們常有稍縱即逝的靈感或感官記憶（如聽到的聲音、腦海中的畫面），這些記憶難以單靠文字或純聲音記錄。感官封存模組旨在提供一個直覺的介面，將使用者的語音紀錄轉化為文字，再進一步轉化為具象的視覺圖像，達成多感官的數位封存。
- **目標用戶**：創作者、寫作者、需要記錄靈感的人、以及想要保存特殊時刻回憶的普通用戶。
- **核心價值主張**：提供「語音 -> 文字 -> 圖像」的一站式無縫轉換體驗，降低靈感記錄的門檻，並賦予聲音記憶視覺化的新生命。

## 2. 功能需求
1. **音訊錄製與上傳功能**
   - 作為使用者，我希望能在網頁上直接錄音，以便隨時捕捉當下的聲音或靈感。
   - 作為使用者，我希望能上傳已有的音訊檔 (MP3, WAV等)，以便將過去的紀錄進行封存。
2. **音訊播放與管理**
   - 作為使用者，我希望能播放剛剛錄製或上傳的音訊，以便確認內容無誤。
3. **文字提煉 (語音轉文字 STT)**
   - 作為使用者，我希望系統能自動將我的音訊轉換成文字，以便我能快速閱讀和編輯音訊內容。
   - 作為使用者，我希望能手動修改轉換後的文字，以便修正語音辨識的錯誤或補充細節。
4. **AI 繪圖生成**
   - 作為使用者，我希望能根據提煉出（或修改後）的文字，一鍵生成對應的 AI 圖像，以便將抽象的聲音記憶具象化。
   - 作為使用者，我希望能選擇不同的繪圖風格（如寫實、水彩、賽博龐克等），以便圖像更符合我心中的意境。
5. **感官封存紀錄儲存**
   - 作為使用者，我希望能將音訊、提煉的文字與生成的圖片一起儲存為一筆「封存紀錄」，以便日後隨時回顧。

## 3. 非功能需求
- **技術限制**：
  - 前端：HTML/CSS/JS (需使用 Web Audio API 進行錄音)
  - 後端：Flask + Jinja2
  - 資料庫：SQLite
  - 外部 API：需串接語音轉文字 API (如 OpenAI Whisper 或 Google Speech-to-Text) 以及 AI 繪圖 API (如 OpenAI DALL-E, Midjourney 或是 Stable Diffusion)。
- **效能與安全考量**：
  - 音訊檔案上傳需限制檔案大小 (例如 10MB 內) 與格式 (MP3/WAV/Ogg/WebM)，避免伺服器儲存空間耗盡。
  - 呼叫外部 AI API 可能有延遲，前端需有明確的載入中 (Loading) 動畫提示，提升使用者體驗。
  - 使用者資料與音訊檔/圖片檔需妥善存放於伺服器指定資料夾 (如 `static/uploads/`)。

## 4. MVP 範圍
- **Must Have (必須有)**：
  - 音訊上傳功能。
  - 串接 STT API 將音訊轉為文字。
  - 串接 AI 繪圖 API 根據文字生成圖片。
  - 簡單的結果展示頁面（顯示音訊播放器、文字、圖片）。
- **Should Have (應該有)**：
  - 網頁端直接錄音功能。
  - 允許使用者在生成圖片前編輯與修改提煉出來的文字。
  - 將整筆資料（音檔路徑、文字、圖片路徑）存入 SQLite 資料庫，並提供歷史紀錄列表頁面。
- **Nice to Have (可以有)**：
  - 多種 AI 繪圖風格選擇。
  - 社群分享功能（將封存紀錄分享給他人）。
  - 音訊波形視覺化。
