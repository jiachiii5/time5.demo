# PRD 產品需求文件：數位時光膠囊 (Digital Time Capsule)

## 1. 專案概述
### 1.1 動機與背景
在步調快速的現代社會中，人們經常因為忙碌而忘記了當下的初衷、情緒或對未來的期許。傳統的紙本信件容易遺失或損壞，且缺乏互動性。因此，我們希望透過「數位時光膠囊」系統，讓使用者能安全地封存當下的文字與心情。這不僅是一個紀錄工具，更是一種與「未來的自己」跨時空對話的方式，在特定時間點解鎖時，提供情緒價值與自我反思的機會。

### 1.2 目標用戶
- 熱愛記錄生活的任何人
- 追求視覺與美感的統一
- 需要碎片化紀錄與多模態整合
- 尋求回顧與發現的驚喜感

### 1.3 核心價值主張與目標
- **目標一**：解決因為忙碌忽視生活中的美好瑣事，提供快速方便的紀錄管道。
- **目標二**：方便查找特定時間的回憶，隨時喚醒過去的記憶。
- **目標三**：建立有設計感的回顧圖片發至社群媒體，滿足分享與自我表達的渴望。

## 2. 功能需求

### 主要功能與使用者故事

1. **隨機遞送與地圖生成**
   - **作為** 系統/發送者，**我希望** 能透過演算法在指定範圍內（如：市區）隨機生成多個包裹/訊息的掉落點，**以便** 讓用戶有豐富的目標可以探索。
   - **作為** 使用者，**我希望** 可以在地圖畫面上看到附近未解鎖的虛擬包裹或觸發點標示，**以便** 決定我的移動路線。

2. **GPS 定位與地圖圍欄（Geofencing）偵測**
   - **作為** 使用者，**我希望** 系統能即時追蹤我的手機 GPS 位置，**以便** 讓我知道我距離目標還有多遠。
   - **作為** 系統，**我希望** 當使用者進入包裹設定的半徑範圍（例如：50公尺內）時，能自動改變狀態為「可解鎖」，**以便** 確保使用者真的到達了現場。

3. **觸發與解鎖機制**
   - **作為** 使用者，**我希望** 當我抵達地圖圍欄範圍內時，能收到通知並點擊「解鎖」按鈕，**以便** 獲取包裹內的隱藏訊息、圖片或任務獎勵。

4. **歷史紀錄與收集冊**
   - **作為** 使用者，**我希望** 能在個人頁面查看我已經成功解鎖的包裹紀錄與內容，**以便** 回顧我的探索足跡與成就。

5. **包裹/訊息創建（UGC）**
   - **作為** 使用者，**我希望** 能夠自己創建一段訊息或虛擬寶物，並指定一個地理座標將其「埋藏」，**以便** 讓朋友或其他隨機用戶來尋找與解鎖。

## 3. 非功能需求

### 技術限制
- 前端網頁需支援行動裝置的 GPS 硬體存取（HTML5 Geolocation API）。
- 後端使用 Flask 框架，搭配 Jinja2 模板引擎進行畫面渲染。
- 資料庫暫定使用 SQLite，儲存用戶資料、包裹座標與解鎖狀態。

### 效能與安全考量
- **定位精準度與防作弊**：需考慮 GPS 訊號漂移的問題，給予適當的緩衝半徑；未來可考慮加入防偽造 GPS（Spoofing）的基礎阻擋。
- **伺服器效能**：隨機生成的演算法應避免在短時間內過度消耗運算資源，可採用批次生成或區域生成。
- **隱私權**：必須取得用戶的定位權限同意，且用戶的即時位置資料不應被不當留存或外洩。

## 4. MVP 範圍

### Must Have (必須擁有 - MVP 核心)
- 靜態/隨機生成的三個測試包裹點。
- 顯示當前使用者位置與包裹位置的地圖介面。
- 進入 50 公尺範圍內的 GPS 圍欄偵測與狀態切換。
- 點擊按鈕成功解鎖並顯示一段純文字的隱藏訊息。

### Should Have (應該擁有)
- 使用者註冊與登入系統。
- 解鎖過的歷史紀錄列表。
- 用戶可以自行輸入座標與文字，創建新的包裹。

### Nice to Have (可以擁有 - 未來擴充)
- AR 鏡頭解鎖模式。
- 路線導航指引。
- 與實體店家的優惠券綁定。
- 好友系統或排行榜。
